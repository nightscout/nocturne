# One-click VM images

The machine images behind Nocturne's cloud marketplace listings (AWS, Azure, Google Cloud,
DigitalOcean). Each is stock Ubuntu 24.04 with Docker and the release's images already pulled.

## What a new machine does

1. `nocturne-firstboot.service` runs `firstboot.sh` once. It writes `/opt/nocturne/.env` from
   `bundle/.env.example`, fills each variable listed in `bundle/generated-secrets` with a fresh
   secret, and records the cloud instance ID as the setup claim code, along with the public
   address.
2. `nocturne-setup.service` runs the `selfhost-setup` Compose service on port 80. The owner enters
   the instance ID and picks a DuckDNS name or their own domain. The service writes `BASE_DOMAIN`
   to `.env`, creates `.setup-complete` and exits.
3. `nocturne.service` starts the stack. Caddy takes ports 80 and 443 and fetches certificates, and
   the owner creates their account at `https://<domain>/setup`.

Watchtower keeps the containers on the release's image tags.

## Layout

| Path | Source |
|---|---|
| `bundle/` | Generated by `scripts/publish-release.cs` from the Aspire AppHost, with `Aspire:OptionalServices:SelfHostSetup` enabled. Do not edit it. |
| `firstboot.sh`, `systemd/` | Hand-written. `VmBundleTests` pins them to the bundle and to `ServiceNames.SelfHost`. |
| `packer/` | One Packer source per cloud. All of them run `provision.sh` and then `cleanup.sh`. |

## Building

```bash
dotnet run scripts/publish-release.cs          # regenerate bundle/
packer init deploy/vm/packer
packer build -var version=1.2.3 -only='digitalocean.nocturne' deploy/vm/packer
```

Credentials come from each cloud's usual environment variables:

- DigitalOcean: `DIGITALOCEAN_API_TOKEN`
- AWS: the AWS CLI profile
- Azure: `az login` and `AZURE_SUBSCRIPTION_ID`
- Google Cloud: `gcloud auth application-default login` and `GOOGLE_CLOUD_PROJECT`
