# Alert Engine Semantics (Normative)

This document freezes the observable behaviour of the leaf/node alert evaluation engine
ahead of its port to the shared Rust crate (`nocturne-alerts-core`). Every statement here
is **normative**: the Rust engine must reproduce it bit-for-bit, including behaviours that
look like bugs. Deviations are parity failures. Where a behaviour is suspected to be
unintentional it is marked **[anomaly]** — fixing it is a separate, deliberate change made
*after* cutover, in both engines never just one.

Source of truth at time of writing:

- `src/Core/Nocturne.Core.Models/AlertModels.cs` (ConditionNode + payload records)
- `src/Core/Nocturne.Core.Models/Alerts/LeafIdentity.cs`
- `src/API/Nocturne.API/Services/Alerts/Evaluators/*` (registry, 30+ evaluators, ConditionPath)
- `src/API/Nocturne.API/Services/Alerts/ExcursionTracker.cs`
- `src/API/Nocturne.API/Services/Alerts/AlertOrchestrator.cs`, `AlertSweepService.cs`, `AlertReplayService.cs`

The machine-checkable form of this document is the golden corpus in
`tests/Parity/AlertEngineCorpus/`, generated by
`tests/Parity/Nocturne.Alerts.ParityCorpus.Generator/` while the C# engine is still
authoritative.

## 1. Wire format

### 1.1 JSON options

All condition JSON (rule `condition_params`, `auto_resolve_params`, snooze `conditions`)
is read with:

- property naming: **snake_case lower** (`JsonNamingPolicy.SnakeCaseLower`)
- property name matching: **case-insensitive**
- `System.DayOfWeek` accepts **string names** (`"monday"`, case-insensitive) **and**
  integer indices (0 = Sunday … 6 = Saturday); canonical output form is the string
- enums with `JsonStringEnumMemberName` use their snake_case wire names
  (`TempBasalMetric`: `rate` | `percent_of_scheduled`; `GlucoseBucket`: `very_low` | `low`
  | `tight_range` | `in_range` | `high` | `very_high`; `AlertComparisonOperator`:
  `>` `>=` `<` `<=` `==`)
- **exception:** `StateSpanCategory` and `PumpModeState` carry a plain
  `JsonStringEnumConverter` with no member-name overrides — their wire form is the
  **PascalCase member name** (`"Override"`, `"PumpConnectivity"`, `"Automatic"`,
  `"EaseOff"`, …), read case-insensitively

### 1.2 ConditionNode

A node is `{ "type": "<discriminator>", "<payload-field>": { … } }`. The payload field
name equals the type string for every kind (e.g. `"threshold": {…}`,
`"rate_of_change": {…}`, `"alert_state": {…}`). Exactly one payload is expected; the
engine only ever reads the payload matching `type`.

- `type` is matched **lowercase-invariant** (`"Threshold"` and `"threshold"` are the same
  kind) at every dispatch site.
- **Unknown `type` ⇒ the node evaluates `false`** (never throws). Same for a known type
  whose payload field is null/absent: the dispatcher serialises the missing payload as
  `{}`, and every payload deserialisation that yields null (or a record failing its
  null-guards) returns `false`. "Silent-false" is the universal failure mode: malformed
  rules never crash evaluation, they just never fire.
- The full discriminator set (30 kinds + `signal_loss`, see §5) is the
  `AlertConditionType` enum's `EnumMember` values.

### 1.3 Numerics

C# evaluates glucose/rate/IOB/etc. as `decimal` (28-29 significant digits, exact decimal
representation). Comparisons like `5.5 == 5.5` and boundary cases (`>=` at exactly the
threshold) are exact-decimal. **The Rust engine must use `rust_decimal`** (or equivalent
exact-decimal arithmetic) for every value that flows through `ComparisonOps`; binary
floats are not acceptable.

Elapsed-time leaves are mixed:

- `staleness`, `loop_stale`, `loop_enaction_stale`, `site_age`, `sensor_age` compute
  elapsed as `(decimal)(now - anchor).TotalMinutes/Hours/Days` — i.e. **`double`
  arithmetic first, then cast to decimal**, then exact-decimal comparison.
- `alert_state` (`for_minutes`), `pump_suspended`, `override_active`, `do_not_disturb`,
  `pump_state`, `state_span_active`, `sustained`, `time_since_last_carb/bolus` compare in
  **`double`** (`.TotalMinutes >= forMinutes`).

The corpus pins boundary behaviour; the practical rule for the port is: replicate the
*comparison operator and inclusivity*, and keep elapsed-time math in f64 where C# used
double, converting to decimal only where C# casts.

## 2. Tree structure, leaf identity, and paths

### 2.1 Containers

Exactly three kinds are containers: `composite` (N children), `not` (1 child),
`sustained` (1 child). Everything else is a leaf.

A container whose payload is null/absent (e.g. `{"type":"composite"}` with no
`composite` field) is **treated as a leaf** by the identity walk and the path walk (the
`when`-guards fail, so the walkers fall through to the leaf branch). It still evaluates
`false`. **[anomaly — but normative]**

### 2.2 Leaf IDs (`LeafIdentity.AssignLeafIds`)

Pre-order depth-first, left-to-right. Containers are unwrapped (never receive IDs);
every non-container node gets the next sequential ID starting at 0. ID space is
per-rule-tree per call.

### 2.3 Condition paths (`ConditionPath`)

Paths are the **persistent identity for sustained timers** (`alert_condition_timers`
keyed by `(rule_id, path)`). The Rust crate owns path generation and must match
byte-for-byte:

- Root segment: the root node's kind, **no index**.
  - In the live orchestrator the root path is the **canonical wire string** of the
    rule's `ConditionType` (`AlertConditionTypeNames.ToWireString`), regardless of how
    the stored JSON spells it.
  - Auxiliary evaluation scopes use reserved roots instead: **`auto_resolve`** (both the
    per-reading and sweep auto-resolve paths) and **`snooze`** (smart-snooze condition
    evaluation). Same `(rule_id, path)` timer rows are intentionally shared between the
    per-reading and sweep variants of the same scope.
- Each descendant appends `[{childIndex}].{child.Type}` where `child.Type` is the
  **verbatim string from the stored JSON** (case preserved — a rule stored with
  `"Type": "Threshold"` produces `…[0].Threshold`). `not` and `sustained` children are
  always index `[0]`.
- Example: `composite[0].sustained[0].threshold`, `composite[1].not[0].iob`.

### 2.4 Evaluation order

`composite` evaluates children **in document order with short-circuit**: `and` stops at
the first false child, `or` stops at the first true child. Children skipped by
short-circuit are **not evaluated at all** — observable because a skipped `sustained`
child neither sets nor clears its timer.

The replay path additionally force-evaluates **every leaf in isolation** (no
short-circuit) to build the per-leaf transition log; leaves are evaluated with the
**rule-root context path**, not their tree path (irrelevant for stateless leaves;
containers are never force-evaluated). A leaf evaluation that throws is recorded `false`.

## 3. Leaf semantics

Shared comparison helper (`ComparisonOps.Compare(actual, op, threshold)`): operators are
the exact strings `<` `<=` `>` `>=` `==`; **any other string ⇒ false**. All comparisons
below are non-strict/strict exactly as written.

| Kind | Payload | Inputs | Semantics | Null / cold-start behaviour |
|---|---|---|---|---|
| `threshold` | `direction` (`above`\|`below`, lowercased), `value` | `LatestValue` | below: `v < value`; above: `v > value` (**strict**) | `LatestValue` null ⇒ false; unknown direction ⇒ false |
| `rate_of_change` | `direction` (`rising`\|`falling`), `rate` | `TrendRate` (mg/dL/min) | falling: `rate' <= -rate`; rising: `rate' >= rate` (**inclusive**) | `TrendRate` null ⇒ false |
| `staleness` | `operator`, `value` (minutes, int) | `LastReadingAt`, `LatestTimestamp`, now | `Compare((decimal)(now-last).TotalMinutes, op, value)` | both `LastReadingAt` and `LatestTimestamp` null ⇒ **false** (cold start); only `LastReadingAt` null ⇒ elapsed = +∞: `>`/`>=` ⇒ true, others ⇒ false |
| `predicted` | `operator`, `value`, `within_minutes` | `Predictions[]` | true if **any** point with `OffsetMinutes <= within_minutes` satisfies `Compare(point.Mgdl, op, value)`; points beyond horizon are skipped, not range-checked below | empty predictions ⇒ false |
| `trend` | `bucket` (wire string) | `TrendBucket` | case-insensitive equality of wire forms (`rising_fast` … `falling_fast`, `unknown`) | `TrendBucket` null ⇒ false; empty/unknown configured bucket ⇒ false |
| `time_of_day` | `from`, `to` (`HH:mm` exact, invariant), `timezone` (IANA, nullable) | now | half-open `[from, to)` in resolved tz; `from > to` wraps midnight (`current >= from \|\| current < to`) | unparseable from/to ⇒ false. Tz resolution: per-rule tz set but unknown ⇒ **false**; else tenant tz (`TenantTimeZoneId`), unknown tenant tz ⇒ **UTC**; both absent ⇒ UTC |
| `iob` | `operator`, `value` (units) | `IobUnits` | `Compare` | null ⇒ false |
| `cob` | `operator`, `value` (grams) | `CobGrams` | `Compare` | null ⇒ false |
| `reservoir` | `operator`, `value` (units) | `ReservoirUnits` | `Compare` | null ⇒ false |
| `site_age` | `operator`, `value` (**hours**) | `LastSiteChangeAt`, now | `Compare((decimal)(now-anchor).TotalHours, op, value)` | null ⇒ false |
| `sensor_age` | `operator`, `value` (**days**) | `LastSensorStartAt`, now | `Compare((decimal)(now-anchor).TotalDays, op, value)` | null ⇒ false |
| `alert_state` | `alert_id` (Guid), `state`, `for_minutes?` | `ActiveAlerts[alert_id]`, now | `firing`: snapshot.State == "firing" (ci). `unacknowledged`: State == "firing" **and** AcknowledgedAt null. `acknowledged`: AcknowledgedAt non-null (State irrelevant). | `loop_enaction_stale` | `operator`, `minutes` | `LastApsEnactedAt`, `HasEverApsCycled` | same as `loop_stale` against the enacted timestamp | same guards (note: guard is `HasEverApsCycled`, not a separate enaction flag) |
| `pump_suspended` | `is_active`, `for_minutes?` | `ActivePumpSuspension`, `HasEverPumpSnapshot`, now | `(suspension != null) == is_active`; then if `for_minutes` set **and** `is_active` true: `(now - StartedAt).TotalMinutes >= for_minutes` (double); `for_minutes` with `is_active:false` is a no-op (true) | `HasEverPumpSnapshot` false ⇒ false |
| `pump_battery` | `operator`, `value` (%) | `PumpBatteryPercent`, `HasEverPumpSnapshot` | `Compare` | guard false ⇒ false; percent null ⇒ false |
| `temp_basal` | `metric` (`rate`\|`percent_of_scheduled`), `operator`, `value` | `ActiveTempBasal` | `rate`: compare `Rate` (U/hr). `percent_of_scheduled`: compare `Rate / ScheduledRate * 100` (decimal division) | no active temp ⇒ false (**no** HasEver guard, by design); `ScheduledRate` null or 0 ⇒ false |
| `uploader_battery` | `operator`, `value` (%) | `UploaderBatteryPercent`, `HasEverUploaderSnapshot` | `Compare` | guard false ⇒ false; percent null ⇒ false |
| `override_active` | `is_active`, `for_minutes?` | `ActiveOverride`, now | same shape as `pump_suspended` | **no** HasEver guard (absence of override is legitimate) |
| `sensitivity_ratio` | `operator`, `value` | `SensitivityRatio`, `HasEverApsSensitivity` | `Compare` | guard false ⇒ false; ratio null ⇒ false |
| `do_not_disturb` | `is_active`, `for_minutes?` | `ActiveDoNotDisturb`, now | same shape as `pump_suspended` (anchor `StartedAt`); `for_minutes` no-op on the inactive side | no guard; snapshot null = DND off |
| `glucose_bucket` | `buckets: [..]` | `GlucoseBucket` | set membership | bucket null ⇒ false; empty/missing buckets list ⇒ false |
| `time_since_last_carb` | `operator` (enum), `minutes` | `LastCarbAt`, now | elapsed minutes (double) compared via `AlertComparisonOperator`; **null anchor ⇒ elapsed = +∞** (so `>`/`>=` fire on cold start — intentional, opposite of loop_stale) | `==` against +∞ ⇒ false; unknown op ⇒ false |
| `time_since_last_bolus` | same | `LastBolusAt` | same | same |
| `day_of_week` | `days: [..]` (string names or ints) | `TenantTimeZoneId`, now | local `now.DayOfWeek ∈ days` | empty/missing days ⇒ false; tenant tz null/unknown ⇒ UTC |
| `pump_state` | `mode`, `is_active`, `for_minutes?` | `ActivePumpState` | `is_active:false`: true whenever active mode ≠ `mode` (**including no active span**). `is_active:true`: mode must match; `for_minutes` anchors at `StartedAt` (double, `>=`) | no guard |
| `state_span_active` | `category`, `state?`, `is_active`, `for_minutes?` | `ActiveStateSpans[(category, state)]` | `category == pump_mode` ⇒ **always false** (defence in depth). `is_active:false`: true iff no snapshot under the exact `(category, state)` key (null state = "any of category" — the enricher loads that key shape). `is_active:true`: snapshot must exist; `for_minutes` anchors at `StartedAt` | no guard |

`composite` / `not` / `sustained` (containers):

- **`composite`** — `{operator, conditions[]}`. Null payload or empty `conditions` ⇒
  false. Operator lowercased; only `and` / `or` are recognised, anything else ⇒ false.
  Short-circuits (§2.4). A child of unknown kind evaluates false (which makes an `and`
  false and leaves an `or` undecided).
- **`not`** — `{child}`. Missing child ⇒ **false** (not true). Otherwise inverts the
  child. Consequence: `not` over an unknown/unregistered child kind ⇒ child false ⇒
  **not ⇒ true**. **[normative]**
- **`sustained`** — `{minutes, child}`. Null child or `minutes <= 0` ⇒ false. Each
  evaluation: evaluate child first (path-extended), then:
  - child false ⇒ **clear** the `(rule_id, path)` timer, return false;
  - child true, no timer ⇒ **set** timer to `now`, return **false** (a 0-elapsed check
    does not happen on the set tick);
  - child true, timer exists ⇒ return `(now - first).TotalMinutes >= minutes` (double).
  - The timer key path is the path **of the sustained node itself**, not the child.
  - Note `minutes` must be `> 0`; a `sustained{minutes:0}` never fires.

## 4. SensorContext

The context is assembled host-side (enricher in the backend; local assembler in
Prelude). For the crate it is pure input data. Fields and their consumers are the table
in §3 plus:

- `CurrentRuleId` / `CurrentPath`: threading state for sustained timers; provided by the
  driver (orchestrator/sweep/replay), maintained by the container evaluators as they
  descend.
- Cold-start flags `HasEverApsCycled`, `HasEverPumpSnapshot`, `HasEverUploaderSnapshot`,
  `HasEverApsSensitivity`: distinguish "never had this data" from "data is old/absent".
  Guarded leaves are listed in §3. Facts whose absence is naturally meaningful
  (`ActiveTempBasal`, `ActiveOverride`, `ActiveDoNotDisturb`, `ActivePumpState`,
  state spans) have **no** flag.
- `ActiveAlerts`: `Dictionary<Guid, {State, TriggeredAt, AcknowledgedAt}>` — live state
  of *other* rules, for `alert_state`. State strings observed: `"firing"` (open
  excursion); `AcknowledgedAt` non-null marks acknowledged.
- Timezone resolution order (where applicable): per-rule condition timezone → tenant
  timezone (`TenantTimeZoneId`, IANA id) → UTC. Failure modes differ by leaf (§3:
  `time_of_day` fails closed on a bad per-rule tz, falls back on a bad tenant tz).

## 5. `signal_loss` is not part of the evaluation core

`signal_loss` exists in the type enum and payload model but **has no registered
evaluator**:

- As a rule's root `ConditionType`, the orchestrator finds no evaluator, logs a warning,
  and **skips the rule entirely** (no tracker call).
- As a node inside a tree, dispatch returns **false** (silent-fail path).
- The real signal-loss behaviour lives in `AlertSweepService.EvaluateSignalLossAsync`
  (30 s cadence): for each enabled rule with `ConditionType == SignalLoss`, parse
  `{timeout_minutes}`, compare `now - tenant.LastReadingAt` (null ⇒ `DateTime.MinValue`,
  i.e. infinitely stale) against the timeout, and on breach call
  `ProcessEvaluationAsync(rule, conditionMet: true)`.
- **The sweep never feeds `false`** — a signal-loss excursion is never closed by signal
  restoration through this path. **[anomaly — host-side]**

For the port: `signal_loss` stays host-side (it needs wall-clock scheduling, not a
reading). The crate treats it as an unknown kind (false in trees). Prelude's local
engine should implement the equivalent staleness watchdog host-side too.

## 6. Excursion state machine (`ExcursionTracker`)

Per-rule persisted state: `{State, ConfirmationCount, ActiveExcursionId, UpdatedAt}` with
states `idle | confirming | active | hysteresis`. Rule inputs: `ConfirmationReadings`
(default 1), `HysteresisMinutes`. One evaluation = one `ProcessEvaluationAsync(ruleId,
conditionMet)` call. **After every call**, regardless of transition, `state.UpdatedAt =
now` is persisted. Unknown stored state string ⇒ no-op transition `None`.

| State | met | Result |
|---|---|---|
| idle | false | None |
| idle | true | `ConfirmationReadings <= 1` ⇒ open excursion → **active**, emit `ExcursionOpened`. Else → **confirming**, `ConfirmationCount = 1`, emit None |
| confirming | false | → **idle**, count reset, None (a single false fully resets confirmation) |
| confirming | true | `++ConfirmationCount`; if `count >= ConfirmationReadings` ⇒ open → **active**, `ExcursionOpened` (count resets to 0 on open) |
| active | true | `ExcursionContinues` |
| active | false | → **hysteresis**, stamp `HysteresisStartedAt = now` on the excursion row, emit `HysteresisStarted` |
| hysteresis | true | → **active**, clear `HysteresisStartedAt`, emit `HysteresisResumed` |
| hysteresis | false | expiry check (below). Expired ⇒ close excursion → **idle**, emit `ExcursionClosed(reason: hysteresis)`; else None |

### 6.1 Hysteresis expiry quirk **[anomaly — but normative]**

The per-evaluation expiry check uses `state.UpdatedAt` as the "hysteresis start" proxy:
`expired = now >= state.UpdatedAt + HysteresisMinutes`. But `UpdatedAt` is rewritten
after **every** evaluation — so on consecutive evaluations in hysteresis the proxy
slides forward. Effective per-reading behaviour: the window expires only when the gap
between two consecutive evaluations is `>= HysteresisMinutes`. With 5-minute readings,
`HysteresisMinutes <= 5` closes on the next reading; `HysteresisMinutes > 5` would
*never* close via this path.

In production that is masked by the sweep: `CloseHysteresisWindowsAsync` (every 30 s)
force-closes **every** open excursion with `HysteresisStartedAt != null` — it does
**not** check `HysteresisMinutes` at all. Net live behaviour today: hysteresis ends
within ~30 seconds of the condition clearing, regardless of configuration.

Port boundary: the crate reproduces the tracker exactly (including the sliding proxy);
the sweep's force-close-all stays a host decision. The corpus pins the tracker; the
sweep anomaly is recorded here so nobody "fixes" the tracker to match the comment above
it.

### 6.2 Force-close

`ForceCloseAsync(ruleId, reason)` (used by auto-resolve, manual close, sweep): if the
tracker has an `ActiveExcursionId` (any state), close the excursion, reset to idle,
emit `ExcursionClosed(reason)`; otherwise None. `GetActiveExcursionIdAsync` returns the
id only in `active`/`hysteresis` states.

## 7. Per-evaluation driver sequence (orchestrator contract)

For each enabled rule on each reading (after `RuleReferenceResolver.FilterEvaluable`
drops `alert_state` chains whose parents are disabled/deleted — host-side):

1. Root context: `CurrentRuleId = rule.Id`, `CurrentPath = wire(rule.ConditionType)`.
2. `conditionMet` = evaluate the rule tree.
3. `transition` = tracker.ProcessEvaluation(rule, conditionMet).
4. Open/close side effects (instances, delivery, DND suppression, info auto-ack) —
   host-side, out of crate scope.
5. **Unconditionally** (even on the same tick as an open), if `AutoResolveEnabled` and
   `AutoResolveParams` non-blank and an active excursion exists: deserialise the
   auto-resolve tree; evaluate it with `CurrentPath = "auto_resolve"`; if true,
   force-close with reason `auto`. A malformed auto-resolve JSON is skipped silently.
   Consequence: a rule whose resolve predicate is already true when its body opens
   produces an open + close pair on the same tick.

Evaluation errors in one rule are caught and logged; remaining rules still evaluate.

DND suppression of **delivery** (non-critical, non-`AllowThroughDnd` rules while
`ActiveDoNotDisturb != null`) is a dispatch-time decision and stays host-side; the
`do_not_disturb` *leaf* (§3) is in the crate.

## 8. Replay semantics (crate's replay driver)

Replay re-evaluates stored rules over a historical window at a fixed **5-minute tick**
with a fake clock, a **fresh in-memory timer store**, and these conventions:

- Rules are **topologically sorted** by `alert_state` references (parents before
  children); cycles fall back to insertion order.
- Per tick, glucose is snapped to the most recent reading at-or-before the tick;
  no-data ticks clamp `LastReadingAt = tick` (staleness reads as 0, not ∞).
- Root truth uses the normal evaluators (short-circuit, shared timer store); leaf log
  uses force-eval of every leaf (no short-circuit, same context, root path). Points are
  recorded on first observation and on every flip (`LeafTransitionPoint(atMs, value)`,
  unix-ms).
- Firing state is tracked per rule replay-locally: `met && !wasFiring` ⇒ `Fired` event
  (or `SuppressedByDnd` under the same gate as live delivery suppression — but the
  active-alerts entry is seeded either way); `!met && wasFiring` ⇒ silent clear (no
  event) **plus `ClearAllForRule` on the timer store**; auto-resolve mirrors §7 step 5
  (evaluated only while firing) and emits `AutoResolved`, removes the active-alerts
  entry, and clears the rule's timers.
- `ActiveAlerts` is a single mutable map shared across the whole replay pass so
  same-tick parent fires are visible to children later in the topo order
  (`ActiveAlertSnapshot("firing", tick, null)`).
- The excursion tracker (confirmation/hysteresis) is **not** consulted in replay —
  replay events are condition-truth edges, not tracker transitions.

The crate exposes this as a deterministic replay driver taking pre-enriched per-tick
contexts; window resolution, reading fetch, and fact-timeline capture stay host-side.

## 9. Out of scope for the crate (stays host-side)

- Context enrichment (`SensorContextEnricher` / Prelude's local assembler)
- Persistence of timers (`alert_condition_timers`), tracker state, excursions, instances
- Delivery channels, DND dispatch suppression, info auto-ack
- Sweep scheduling (30 s cadence), signal-loss watchdog (§5), hysteresis force-close (§6.1)
- Smart snooze policy (extend/clear, max counts, trend-favorable heuristic) — but note
  snooze *conditions* are evaluated through the normal node dispatch with
  `CurrentPath = "snooze"`, wrapped as `composite{and, [conditions]}`; that evaluation
  goes through the crate.

  The predicate is corpus-covered: a scenario rule may carry `snooze_conditions`, and the
  runners record its truth as `snooze_extend` plus any timer ops the tree produced, after
  the rule body's. Note the corpus is the *only* cross-engine check on this scope —
  `ShadowAlertEngine` shadows `EvaluateRuleAsync` alone, so `EvaluateNodeAsync` (and its
  `root` override) never diverge-logs against production traffic.
- Rule CRUD, validation, `RuleReferenceResolver.FilterEvaluable`, topo-sort inputs
