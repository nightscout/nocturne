# nocturne-alerts-core

Nocturne's alert condition engine in Rust, used by the .NET backend through
[`nocturne-alerts-ffi`](../nocturne-alerts-ffi) and by Prelude on Android
through its UniFFI bindings. The normative spec is
[`docs/alerts/engine-semantics.md`](../../docs/alerts/engine-semantics.md),
including the behaviours its anomalies index keeps on purpose. Its
machine-checkable form is the golden corpus in
[`tests/Parity/AlertEngineCorpus/`](../../tests/Parity/AlertEngineCorpus/),
which `tests/parity.rs` runs scenario by scenario.

## Boundary

The crate is pure evaluation: no I/O, no clock, no persistence.

- `now` is always passed in; nothing reads the wall clock.
- The sensor context ([`context::SensorContext`]) is plain input data
  assembled by the host.
- State lives in caller-owned stores the host persists between evaluations:
  sustained-condition timers ([`sustained::TimerStore`], keyed by rule and
  condition path, recording each set and clear) and the excursion state
  machine ([`excursion::ExcursionTracker`], idle → confirming → active →
  hysteresis, expiring against the persisted `hysteresis_started_at`,
  semantics §6.1, and holding an auto-resolved rule off until its condition is
  false, §6.3).
- Out of scope, host-side: context enrichment, persistence, delivery and DND
  suppression, and sweep scheduling. [`wall_clock::references_wall_clock`]
  says which rules the sweep must evaluate (semantics §5.1).

## Layout

| Module | Contents |
|---|---|
| `model` | condition nodes and payload records, read as semantics §1 specifies; `ParseError` with the offending path |
| `enums` | every enum a payload or context names, parsed once when read; the manifest guard against host drift |
| `context` | `SensorContext`, read from the context wire format |
| `paths` | condition paths: root segment as given, children `[i].{type as written}` |
| `eval` | one module per leaf family, plus dispatch and the composite and `not` containers |
| `sustained` | timer store and the `sustained` container |
| `excursion` | the excursion state machine, including force-close |
| `engine` | the per-rule driver (root → leaf log → tracker → auto-resolve) and the corpus result shape |
| `replay` | the replay driver: a rule set over a series of ticks with replay-local firing state (semantics §8) |
| `validate` | the evaluability check parsing applies and the save-time check hosts apply |
| `classify` | scope classes for scoped Do Not Disturb |
| `wall_clock` | which rules need periodic evaluation |

## Verification

```bash
cd crates
cargo test --workspace --features nocturne-alerts-ffi/uniffi
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo fmt --check
```

The parity suite names the scenario, tick, rule and field of any divergence
from the committed `.expected.json` snapshots. Never fix a divergence by
editing the corpus: it is generated by
`tests/Parity/Nocturne.Alerts.ParityCorpus.Generator`.
